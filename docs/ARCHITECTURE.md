# Архитектура системы

## Обзор системы

MotoTalk - это одноранговая система голосовой связи для двух мотоциклистов, использующая WebRTC для передачи аудио с низкой задержкой.

## Компоненты

### 1. Мобильный клиент (Flutter)
- Кнопка PTT с функцией удержания для разговора
- Режим голосового управления с локальным распознаванием речи
- Интеграция музыки (пауза/возобновление при PTT)
- Потоковая передача аудио через WebRTC
- Сигнализация WebSocket
- Логика автоматического переподключения
- Премиум тёмный интерфейс

### 2. Сервер сигнализации (Node.js)
- Управление соединениями WebSocket
- Сигнализация WebRTC (обмен SDP, ICE-кандидаты)
- Авторизация пользователей (PIN-код)
- Отслеживание статуса соединения
- Минимальное состояние (только 2 пользователя)

### 3. Обработка аудио
- Встроенное подавление шума WebRTC
- Фильтрация шума ветра
- Подавление эха
- Автоматическая регулировка усиления

## Поток данных

### Режим PTT
```
Пользователь удерживает кнопку
  ↓
Музыка ставится на паузу/выключается
  ↓
Микрофон активируется
  ↓
Поток аудио через WebRTC
  ↓
Собеседник получает аудио
  ↓
Пользователь отпускает кнопку
  ↓
Микрофон деактивируется
  ↓
Музыка возобновляется
```

### Режим голосового управления
```
Пользователь говорит "Приём" или "Пуск"
  ↓
Локальное распознавание речи
  ↓
Музыка ставится на паузу
  ↓
Микрофон активируется
  ↓
Непрерывная передача аудио
  ↓
Пользователь говорит "Стоп" или "Отбой"
  ↓
Распознавание останавливает передачу
  ↓
Музыка возобновляется
```

```

│              Поток аудио WebRTC P2P              │

└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│           Канал сигнализации WebSocket           │
│  (Обмен SDP, ICE-кандидаты, зашифровано TLS)    │
└─────────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────┐
│              Сервер сигнализации                 │
│  (Node.js + Socket.io, минимальное состояние)    │
└─────────────────────────────────────────────────┘
```

## Безопасность

- **TLS**: Все соединения WebSocket зашифрованы
- **DTLS**: Шифрование рукопожатия WebRTC
- **SRTP**: Шифрование медиа-потока
- **Авторизация по PIN**: Простой 4-значный PIN для сопряжения
- **Без облачных сервисов**: Только self-hosted

## Управление состоянием

### Состояние сервера (минимальное)
- Подключённые пользователи (максимум 2)
- PIN-коды пользователей
- Статус соединения

### Состояние клиента
- Текущий режим (PTT/Голос)
- Статус соединения
- Статус собеседника
- Состояние музыки
- Состояние аудио-сессии

## Стратегия автоматического переподключения

1. **Отключение WebSocket**: Попытка переподключения с экспоненциальной задержкой (1с, 2с, 4с, 8с, максимум 30с)
2. **Отключение WebRTC**: Повторная инициализация сигнализации и создание P2P соединения
3. **Перезапуск сервера**: Клиент автоматически переподключается при доступности сервера
4. **Изменение сети**: Обнаружение и восстановление соединений

## Оптимизация ресурсов

- Сервер работает на одном ядре (достаточно для 2 пользователей)
- SQLite для минимальной нагрузки базы данных
- Без постоянного хранилища кроме авторизации
- Пулирование соединений не нужно (только 2 пользователя)
- Использование памяти: <100 МБ сервер, <200 МБ на клиента

## Ограничения платформ

### Android
- Ограничения фонового аудио
- Приоритет микрофона Bluetooth
- Требуется foreground service для фоновой работы
- Управление аудио-фокусом

### iOS
- Ограничения фонового аудио
- Рекомендуется интеграция CallKit
- Управление аудио-сессией Bluetooth
- Ограничения жизненного цикла приложения
